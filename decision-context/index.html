Decision Context: Persistent Behavioral Learning for AI Agents

01 //
abstract
tl;dr

LLM agents do not learn from corrections across sessions. A user fixes the same mistake at the start of every conversation. Existing agent memory systems primarily handle facts — preferences, entities, conversational history — rather than procedural knowledge.

We present Forge Decision Context (forge_dc), a system that captures behavioral signals from human corrections and self-assessed tool-call failures, compiles them into imperative RULE directives, and injects them at the decision points where they apply. We evaluate forge_dc alongside four predecessor approaches on DC-Bench, a new benchmark of 71 scenarios across nine behavioral dimensions, built from real executed agent traces in a deterministic mocked-tool environment. forge_dc reaches 95% compliance, up from 55% with naive retrieval, while injecting approximately 10x fewer tokens per query.

Across the five-stage progression, the strongest systems represent behavioral memory as explicit directives and deliver it at the decision points where it applies. The results identify representation, activation, and placement as central design choices for persistent behavioral learning.

04 //
findings
each pairs with a design consideration
finding 01

Directive-form memory produces a recurring compliance advantage — the "Only Rules Rule"

Agents follow compiled behavioral directives more consistently than retrieved descriptive corrections. Behavioral memory has to be optimized for action, not retrieval alone. Consideration: evaluate whether retrieved memory changes behavior, not only whether the correct text was retrieved.

finding 02

Format and content rules retrieve differently

Formatting rules ("include USD") have no embedding similarity to the queries they apply to, so pure semantic retrieval misses them at scale. Consideration: tag rules by type at capture and route them differently at retrieval — embedding similarity is the right primitive for content rules and the wrong one for format rules.

finding 03

Data-conditional rules need to fire at the decision point

Rules that depend on tool data cannot be evaluated at query time; they have to surface when the triggering data appears. Consideration: re-retrieve as the agent accumulates context and add newly triggered rules to the system prompt between tool calls.

finding 04

Adding reasoning to a rule does not help, and sometimes hurts

A variant attaching a one-sentence justification to each rule scored flat or slightly lower than the bare directive on every model tested — given the reason, the model evaluates the directive and sometimes overrides it. Consideration: do not try to convince the model; extra judgment material invites second-guessing.

finding 05

The injection channel is part of the design

Channels carry different trust profiles, compete differently with the task for attention, and dilute when several instruction streams share one slot. What works on one model generation is not guaranteed to work on the next. Consideration: treat each stage's channel as a first-class design decision and re-validate when the model changes.

finding 06

A memory must not regress the base

Injected guidance can make an agent worse than no memory — a rule that surfaces on a case it does not fit degrades an output that needed no change. Consideration: learn only from failures and corrections, and default to staying silent when nothing needs to change.
